# Verified production flow before this pass

AUDIO EVIDENCE != PERCEIVED TEXT != REFERENCE PRONUNCIATION != INTENDED TARGET.

Code inspected before production edits on the existing uncommitted branch:

1. `audio/service.py`: ingest preserves original bytes, canonicalizes to mono 16 kHz PCM WAV, runs the existing speech-presence check, then persists canonical `AudioAsset` (SHA-256, duration) and `Utterance`.
2. `api/routes.py:create_perception`: **already** calls `start_acoustic_warmup` outside the test environment before unknown-target perception. `pronunciation/warmup.py` owns bounded two-worker capacity, duplicate suppression, separate worker sessions, and optional failure fallback. It does not join ASR. This corrects the initial service-only impression that pitch necessarily waits for ASR.
3. `perception/service.py`: canonical bytes + language hint go to unknown-target ASR; no target is supplied. Existing presence checks surround ASR; its persisted transcript is immutable evidence.
4. `pronunciation/acoustics.py`: whole-waveform Praat AC plus its existing high-pass diagnostic extraction; no linguistic input. `AcousticRun` already independently stores raw tracker, energy-gated, selected F0, candidate strengths and filter diagnostics in JSON. Reuse matches utterance, algorithm/version/parameters. All entry points lock the utterance until persistence with PostgreSQL NO KEY UPDATE, permitting perception FK insertion. Explicit administrative rerun requests can append a new run; ordinary repeated analysis reuses evidence.
5. `pronunciation/perceived.py`: requires successful perceived text and the unchanged transcript-aware presence guard. Acoustics (normally warmup cache) and alignment run in parallel closures with no SQL in workers. **Linguistic data first affects pitch interpretation at trusted interval attribution**, not extraction: ASR timestamps or alignment against perceived text. Reading/surface rules separately supply references. Missing character timing remains missing; Azure word-only timing becomes one group.
6. `contours.py`: utterance display selection uses existing energy/quality exclusions, periodicity, short octave-island and local Hampel rejection; smoothing stays within retained runs. Before this pass the classifier repeated selection from saved raw frames per region, then applied acoustic boundary/core heuristics. `syllable_contour` uses [start,end). `tone_graph.py` splits/simplifies for display and retains unsmoothed detail and raw timestamps.
7. `laboratory.py`: known-target assessment/alignment are separate branches; acoustic service is shared. Target text/reading enters target alignment/reference comparison, never raw extraction. Existing explicit rerun controls append evidence.
8. Mobile `speech/workflow.ts`: all Practice, Free Practice and Conversation upload, perceive, then request perceived analysis. Practice target assessment is a separate branch. Conversation meaning/reply proceeds alongside perceived analysis. `SentenceToneGraph` shares these projections; `toneGestureMatch` previously repeated several backend acoustic quality checks before consistent/different.

No database migration or new orchestration is needed. Preserve the existing warmup and lock boundary; introduce an immutable, audio-only typed snapshot in existing AcousticRun JSON and typed interval projections. Legacy saved raw evidence can be wrapped without extracting audio or rewriting history. Tracker research remains closed.
